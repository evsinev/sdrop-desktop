# pnesecrets: десктоп-клиент Payneteasy Secrets

Окно и быстрый ввод по горячей клавише для того же сервиса одноразовых секретов, что веб-клиент
сервиса и `sdrop` (github.com/payneteasy/sdrop). Формат, ссылки и API — `FORMAT.md` и
`CLIENTS.md` в `sdrop`; где задумка интерфейса (далее «ТЗ») расходится с ними, решают они.

## 1. Рамки

- Платформы: macOS 12+ (arm64, x86_64), Windows 10/11 (x86_64), Linux x86_64 (X11 и Wayland).
- Экраны ТЗ: A1 New secret, A2 статус отправленного, боковая панель с историей, C quick drop по
  глобальной клавише, D полученный секрет. Вариант B (popover в menu bar) — вне рамок.
- Вне v1: синхронизация истории между машинами, автообновление, подпись и нотаризация (отдельное
  решение, когда будут сертификаты), universal links на `https://…/s/*`, встроенный вход в Access.

## 2. Стек и зависимости

- UI: GPUI через `gpui-kit` =0.8.0 (фасад longbridge/gpui-component; закрепляет снимок GPUI
  `gpui-pre` =0.3.9; Input с маской, кнопки, переключатели, иконки Lucide).
- `sdrop` — git-зависимость на github.com/payneteasy/sdrop по тегу (сейчас `v0.3.1`, коммит в
  `Cargo.lock`): `format`, `api` (доверенный origin, разбор ссылок, запросы без редиректов),
  `ops::Client` (limits, create, consume, status, revoke), `password` (генератор веба, 24 символа),
  `access` (токен Access). Не берётся `tui::clipboard` (OSC 52 в stdout) и `save` по умолчанию
  (каталоги `sdrop-<id>` — для CLI).
- Платформенные крейты (каждый — по согласованию, точные версии; фактическая работа с GPUI-циклом
  проверяется на шаге 0): `keyring` (хранилище ОС), `global-hotkey` (macOS, Windows, X11),
  `tray-icon` (macOS, Windows) и `ksni` (Linux, StatusNotifierItem без GTK), уведомления
  (`user-notify` или `notify-rust` — по итогам шага 0), `rfd` (диалоги файлов), `arboard` (буфер с
  пометками concealed), `serde`/`serde_json` (индекс истории), `interprocess` (один экземпляр,
  передача команд), `zeroize`.
- Раскладка: workspace из `core` (без GPUI: история, хранилище, буфер, опрос, операции, состояния
  экранов) и `app` (GPUI, окна, платформа). `cargo deny` (advisories, licenses, bans, sources), как
  в `sdrop`.

## 3. Совместимость (неизменяемо)

- Формат конверта, ключ во фрагменте, `~p`, PBKDF2/HKDF, упаковка файлов (v1 text/file, v2
  bundle, до 20 файлов), бакеты и `GET /api/limits`, TTL 3600 / 86400 / 604800, API create /
  consume / status / revoke — строго `sdrop` `FORMAT.md` и `CLIENTS.md`, тем же кодом `sdrop`.
- Ссылки: получателя `<origin>/s/<64 hex>#<43 b64url>[~p]`, отправителя `<origin>/o/<id>#<token>`.
  В макетах укороченные id — только иллюстрация.
- Лимит размера показывается из `maxBucket` сервиса (на проде 262144 → «256 KB»), а не константой.
- Origin вшит при сборке (`SDROP_DEFAULT_ORIGIN`) или задан `SDROP_ORIGIN`; в интерфейсе не
  меняется. Ссылки на другой origin отвергаются до запросов. Поле Server в A2 — хост origin.

## 4. Хранение и граница данных

- **Хранилище ОС** (`keyring`; сервис `com.payneteasy.secrets`, учётная запись = локальный id
  записи истории): на каждую запись — ссылка получателя и ссылка отправителя (`/o/<id>#<token>`;
  две строки `recipient\nowner` в `Zeroizing`, без JSON-разбора с копиями; id секрета берётся только отсюда). Удаляется, когда секрет вышел
  из Waiting (Read, Revoked, Expired, Not found; `consumedBy` к этому моменту уже в индексе), и при
  удалении записи (30 дней). В индексе — флаг `vault` (есть ли элемент): хранилище не перечисляется,
  поэтому при запуске для каждой не-Waiting записи с `vault = true` удаление повторяется. Порядок
  записи: сначала в индекс — локальный id с `vault = pending`, затем элемент хранилища, затем
  `vault = true`; запись истории удаляется из индекса (30 дней) только после успешного удаления
  элемента хранилища. Так ни один элемент хранилища не остаётся без записи в индексе. Нет доступа
  к хранилищу (Linux без Secret Service, отказ пользователя) — создание работает, запись истории
  помечена «not tracked», ссылка показывается только до закрытия A2; это видно в подвале и у
  кнопки Create («Owner link will not be kept: no revoke or read notification after you close
  this») (решение 2026-10-24). Запись «not tracked» никогда не показывает Waiting с
  отслеживанием.
- **Индекс истории** — JSON в каталоге данных приложения (macOS `~/Library/Application Support/
  com.payneteasy.secrets/`, Windows `%APPDATA%\Payneteasy\Secrets\`, Linux
  `$XDG_DATA_HOME/pnesecrets/`), права 0600/0700 на Unix, запись атомарно (temp + rename). Поля:
  локальный id, label, createdAt, expiresAt, TTL, status и время смены, checkedAt и время последней
  проверки со `stored`, notifiedAt, `vault` (есть ли элемент хранилища), passphrase да/нет, notify
  да/нет, тип содержимого (text / files / both) и число строк текста, имена и размеры
  файлов, linkCopiedAt, clipboardClearedAt, consumedAt, consumedBy, хост сервера. Повреждённый
  файл (не наш формат) переносится в `history.json.damaged-<время>`, история начинается пустой —
  с сообщением. Файл, который не читается вообще (права, ввод-вывод), или повреждённый, который
  не удалось перенести, — история недоступна: ничего не пишется поверх, создание отключено до
  исправления (сообщение с причиной), получение работает. **Нет**: текста,
  ключа, ссылок, id секрета на сервере, токенов, фразы. Записи старше 30 дней удаляются при запуске
  и раз в сутки.
- **Память.** Текст, файлы, фраза, конверт — в `Zeroizing` в `core`; после create, Esc и
  уничтожения полученного секрета затираются. **Гарантия ТЗ п. 5 ослаблена** (решение
  пользователя 2026-10-24): GPUI хранит текст полей ввода и отрисованные строки в
  своих буферах (rope и история Undo у Input, кэш раскладки строк), которые мы не затираем. Гарантия
  звучит так: «буферы приложения затираются; копии внутри UI-фреймворка освобождаются без затирания
  и могут оставаться в памяти процесса до перезаписи». Поле очищается сразу после create/Esc вместе
  с историей Undo; окно D уничтожается при закрытии.
- **Логи и сбои.** Никакого логгера по умолчанию; `RUST_LOG` в релизе игнорируется. Хук паники
  пишет только место. Телеметрии и отчётов о сбоях нет. Заголовки окон, тексты уведомлений, пункты
  меню — без содержимого секрета (label — да, он не секрет по определению ТЗ).
- **Аргументы процесса.** Ключ, ссылка получателя и текст никогда не передаются через argv
  (видны в списке процессов): `--quick-drop`, `--open-window` — без данных.

## 5. Буфер обмена

- Одна служба буфера в `core`: копирует (`arboard`, с `org.nspasteboard.ConcealedType` на macOS,
  `ExcludeClipboardContentFromMonitorProcessing`/`CanIncludeInClipboardHistory=0` на Windows,
  `x-kde-passwordManagerHint` на Linux X11, где поддерживается), и через таймаут очищает **только
  если в буфере всё ещё наше значение**: ссылка получателя — 60 с, раскрытый секрет — 30 с. При
  выходе из приложения — то же немедленно.
- «Всё ещё наше» — по счётчику изменений буфера ОС, снятому сразу после нашей записи: macOS
  `NSPasteboard.changeCount`, Windows `GetClipboardSequenceNumber`; не изменился — очищаем без
  чтения текста. Linux (X11, Wayland data-control) счётчика нет: сравнение текста, остаётся гонка
  «прочитали своё → другой процесс записал → очистили чужое» — **принятый риск** на Linux; окно
  гонки — между чтением и очисткой в одном вызове. На macOS/Windows остаётся только окно между
  проверкой счётчика и очисткой (микросекунды).
- Не удалось очистить (буфер занят) — значение остаётся «нашим», очистка повторяется через 1 с,
  при выходе — несколько попыток.
- Время копирования и очистки ссылки пишется в историю (таймлайн A2).
- Все пути копирования из секретных полей — кнопки, `⌘C`/`⌘X`/`Ctrl+C`/`Ctrl+X`, пункты меню Edit
  и контекстного меню в поле секрета A1, поле фразы A1/C, поле C (после Show), тексте D — идут через
  эту службу (у `gpui-base` Input copy/cut пишут в буфер GPUI напрямую — перехватываются своими
  действиями). То же для полей получателя: Open link… (ссылка с ключом) и фраза до и после consume. Ссылка в A2 — тоже через службу. Текст в D не выделяется мышью; копируется целиком
  кнопкой.
- Чтение буфера — только по действию пользователя (Paste from clipboard) и при открытии C (ТЗ):
  если там текст — забрать, показать маской, очистить буфер (если всё ещё тот же текст).

## 6. Главное окно (A)

Окно 1200×780 логических px по умолчанию (как макет), минимум 960×620; системная рамка (на macOS прозрачный
заголовок с «Payneteasy Secrets», как в макетах). Тексты интерфейса — как в макетах.

### Боковая панель
- Логотип payneteasy + «Secrets»; **New secret** (`⌘N`/`Ctrl+N`); поиск по label (локальный,
  без учёта регистра); список «Sent · on this computer», новые сверху: label (или
  «Untitled · <время>»), точка и текст статуса (Waiting · 23 h left / Read · 14:05 / Expired
  · unknown / Revoked / Not found), относительное время (10:42 / Yesterday / Mon / Oct 17).
- Подвал: «✓ Owner links kept in Keychain» (Windows — «Credential Manager», Linux — «system
  keyring»; без хранилища — предупреждение), «Quick drop: ⌘⇧S» (текущая клавиша; на Wayland —
  подсказка про системную клавишу).

### A1 New secret
- Поле секрета (моноширинное, многострочное); **Paste from clipboard**, **Generate password**
  (`sdrop::password`, вставляет в поле).
- Файлы: зона перетаскивания и «choose files» (`rfd`, несколько); перетаскивание на иконку в Dock
  (macOS) открывает A1 с файлами. Список: имя, размер, Remove. Подпись «Up to 20 files, <лимит>».
  Имя файла — базовое, через `sdrop::format::sanitize_file_name`.
- Правая панель: **Label** (только локально); **If nobody opens it, delete after** — 1 hour /
  24 hours (по умолчанию) / 7 days; **Protect with a passphrase** — переключатель и поле (видно при
  вводе) с напоминанием передать другим каналом; **Notify me when it is read** (по умолчанию да).
- **Create and copy link** (`⌘↵`/`Ctrl+Enter`): проверка размера против лимита до шифрования →
  шифрование и POST вне UI-потока → **создано на сервере** (ссылки в памяти `core`, форма
  заблокирована: повторное нажатие второго секрета не создаёт) → локальные действия: элемент
  хранилища, запись индекса, ссылка в буфер → A2 этой записи → форма очищается. Одна операция за
  раз.
- Create после отправки POST не отменяется: Esc в C и закрытие окна скрывают вид, операция
  остаётся у владельца в `core`; поздний 201 предъявляется пользователю (A2 или экран частичного
  успеха; в C — уведомление «Link created» с открытием A2), неизвестный сетевой исход — тоже.
  Координатор выхода учитывает незавершённый create и несохранённый частичный успех. Esc до
  отправки — ничего не остаётся.
- 201 с нечитаемым телом — секрет создан, ссылка потеряна: «result unknown», повторное создание —
  только явной кнопкой (новый секрет), не повтором той же операции.
- Отказ локального действия после 201: секрет не теряется и не создаётся второй — экран «Created,
  but not saved on this computer» со ссылкой получателя, **Copy** и **Retry** (повторяет только
  неудавшиеся действия). Без хранилища запись пишется «not tracked»; без индекса — ссылка только в
  этом экране, пока он открыт.
- Ошибки (сеть, размер, Access, 429) — строкой над кнопкой, форма сохраняется. Сетевой обрыв при
  create — «result unknown», без автоматического повтора.

### A2 Статус отправленного
- Заголовок: label и плашка статуса: **Waiting to be opened** (`#f0b25a`), **Read** (`#4fd1a1`),
  **Expired · read status unknown** (серый), **Revoked** (`#ff8a80`),
  **Not found** (серый: 404 до срока).
- «Link for the recipient»: ссылка (моноширинная) + **Copy**; подпись «Opens once, then the secret
  is destroyed. Nothing to bookmark: this app keeps the owner link for you.» После выхода из
  Waiting блок ссылки скрыт (ссылка удалена из хранилища).
- Timeline: Created and encrypted (время) → Link copied (время · clipboard cleared время) →
  Opened (время, `consumedBy`, если есть) / Not opened yet (Checked N min ago · you will get a
  notification) → Deleted if unread (время) / Revoked (время).
- Details: Expires (in 23 h 12 min / дата), Passphrase Yes/No, Content (Text · N lines / Files /
  Text and files — содержимое никогда), Files (имена, размеры), Server.
- **Revoke** (диалог подтверждения, фокус на Cancel; 409 → статус Read с данными ответа) и **Send
  again** (A1 пустой, с тем же TTL и признаком фразы; секрет не хранится).

### Опрос статуса
- Сервис после `expiresAt` отвечает 404 на всё, включая уже прочитанные (FORMAT.md 6: истёкший
  — тот же 404): исход после срока узнать нельзя. Поэтому опрос — только до срока.
- Только записи в Waiting со ссылкой отправителя в хранилище: каждые 60 с, пока окно A в фокусе,
  каждые 5 мин в фоне, плюс обязательная последняя проверка в `expiresAt − 90 с`; после
  `expiresAt` запросов нет. Последовательно, не больше одного запроса на запись одновременно;
  ошибки сети — повтор на следующем тике, без шума. Сон машины: при пробуждении — проверка сразу,
  если срок не прошёл.
- `consumed` → Read; `revoked` → Revoked; 404 раньше срока → Not found. Срок прошёл без
  подтверждённого терминального ответа → **Expired · read status unknown** (короче в боковой
  панели: «Expired · unknown»); последняя проверка со `stored` показывается отдельным фактом в
  таймлайне («Not opened as of <время>»). Даже проверка за 90 с до срока не доказывает, что секрет
  не прочитали, поэтому «Expired unread» из макета не используется — осознанное расхождение.
- Полученный терминальный ответ (`consumed` с `consumedAt`/`consumedBy`, `revoked`) держится в
  памяти, пока не записан в индекс: повторяется запись, а не запрос status, и он не заменяется
  вычисленным Expired. Подтверждённый ответ (Read, Revoked) никогда не заменяется более слабым
  (Not found, Expired · unknown, поздний `stored`), в каком бы порядке ни пришли ответы опроса и
  Revoke.
- Переход в Read → одно системное уведомление «<label> was read · <время>» (если включено для
  записи); клик открывает A2. Уведомление возможно, только если приложение успело получить
  `consumed` до срока. Порядок: запись индекса (статус, `consumedAt`, `consumedBy`, `notifiedAt`) →
  уведомление → удаление элемента хранилища. Не удалось записать индекс — уведомления нет, повтор на
  следующем тике; сбой между записью и показом — уведомление потеряно (не больше одного).

## 7. Quick drop (C)

- Приложение работает в фоне: иконка в трее/menu bar с пунктами «Open window», «Quit». Закрытие
  окна A не завершает приложение (`QuitMode::Explicit` на всех ОС). Глобальная клавиша, трей,
  клики уведомлений, `open_urls`, опрос статуса принадлежат приложению, а не окну; трей и клик по
  иконке в Dock снова открывают A. Один экземпляр: повторный запуск передаёт команду (`--quick-drop`,
  открыть окно, файлы) работающему через локальный сокет/именованный канал текущего пользователя.
- Глобальная клавиша по умолчанию `⌘⇧S`/`Ctrl+Shift+S`, настраивается. Wayland: глобальных клавиш
  нет — подсказка «назначьте системную клавишу на `pnesecrets --quick-drop`».
- По клавише: панель по центру экрана, поверх всех, в фокусе. Wayland: обычные окна не могут быть
  «поверх всех» — панель открывается как layer-shell overlay (KDE, wlroots-композиторы); на GNOME
  (нет layer-shell) — обычное окно в фокусе, без гарантии «поверх» (ограничение окружения). Буфер
  на Wayland — протокол data-control (`arboard` `wayland-data-control`), без XWayland. Текст в буфере — забирается (раздел
  5), показан маской `••••` с «Pasted from clipboard · N characters · clipboard cleared»; **Show**
  переключает маску; ввод и вставка в панель тоже работают.
- Чипы: Delete after (Tab циклит 1 h / 24 h / 7 d, по умолчанию 24 h), Passphrase (`⌘P`, поле
  фразы), Add files (`⌘O`), Label (`⌘L`).
- `↵` → создать, скопировать ссылку, закрыть панель, уведомление «Link copied — Opens once, deleted
  in 24 h if unread. The clipboard clears in 60 s.»; запись появляется в истории A. Ошибка —
  строкой в панели, введённое сохраняется. `Esc` — закрыть и затереть всё введённое.
- Потеря фокуса панелью не закрывает её молча с данными (данные не теряются и не остаются: панель
  остаётся поверх до `↵`/`Esc`).

## 8. Полученный секрет (D)

- Источники ссылки: File → **Open link…** (`⌘⇧O`/`Ctrl+Shift+O`, поле вставки); схема
  `pnesecrets://s/<id>#<фрагмент>` — только на macOS (приходит через Apple Events, не argv); на
  Windows и Linux — только Open link… (раздел 4, аргументы процесса). Ссылка по схеме разбирается
  так же строго, как `https://`, и приводится к доверенному origin. Кнопка «Open in desktop app» на
  веб-странице — изменение веб-клиента сервиса, отдельное решение.
- Ссылка разбирается до запросов (битая — сообщение, ноль запросов). До раскрытия: окно «Received
  secret», то же предупреждение, что на вебе («It will be destroyed as soon as you reveal it»),
  поле фразы при `~p`, **Reveal secret**. Никакого consume при открытии окна.
- Consume — ровно один, по нажатию. **Сессия получения** живёт в `core` на уровне приложения, не
  окна: Parsed → Consuming → NeedPassphrase (конверт) → Revealed (секрет, отметки сохранения) →
  Destroyed. Окно D — только вид сессии. Закрытие окна во время Consuming сессию не отменяет:
  пришедший результат снова открывает D. Destroyed — только по явному подтверждению пользователя.
  Фраза после consume (флаг без `~p`) или неверная — повтор локально с тем же конвертом, без второго
  consume. Сетевой обрыв во время consume — «result unknown, the secret may already be destroyed»,
  без авто-повтора.
- Окно D 760×640 (макет), панель C 640 px шириной. После раскрытия (макет D): янтарная полоса «Already deleted from the server. Closing this window
  removes it for good.», «Opened from <host> link · время», текст моноширинным шрифтом,
  **Copy · clears in 30 s**, **Save to file…**; список файлов с **Save…**. Файлы сохраняются как
  есть, никогда не открываются и не показываются.
- Сохранение: системный диалог сохранения; предложенное имя — имя отправителя после проверки
  формата и замены недопустимых для ОС символов (Windows: `<>:"|?*`, зарезервированные имена,
  точка/пробел в конце); пишет только в выбранный пользователем путь. Права итогового файла —
  только владелец: Unix — запись во временный файл 0600 в том же каталоге и rename (замена
  существующего файла не наследует его режим); Windows — явная DACL «только текущий пользователь»
  на временном файле до записи данных, затем замена. Не удалось установить права — отказ без
  записи данных. Ошибка — данные остаются в сессии получения, выбрать другое место.
- **Copy — временная копия, не сохранение** (буфер очистится через 30 с и при выходе). Закрытие D
  в состоянии NeedPassphrase или Revealed спрашивает всегда, кроме случая, когда текст и все файлы
  сохранены в файлы: «Destroy this secret? It is already deleted from the server and cannot be
  opened again.» — Cancel (фокус, Esc, Enter) / Destroy. Подтверждение — затирание буферов `core`.
- **Выход приложения** — через один координатор выхода в `core`: пока есть сессия получения не в
  Parsed/Destroyed или открыт C с данными, выход спрашивает (тот же диалог для каждой сессии). Входы:
  меню и `⌘Q`/`Ctrl+Q`, пункт трея — наши действия; Quit из Dock и меню приложения macOS —
  `applicationShouldTerminate:`, добавленный в рантайме в класс делегата GPUI
  (`GPUIApplicationDelegate`) и возвращающий `NSTerminateCancel`, пока координатор не разрешит
  (проверяется на шаге 0; не выйдет — патч GPUI). Windows: закрытие последнего окна не завершает
  приложение (трей). **Принятый риск**: завершение сеанса ОС, перезагрузка, `kill`, сбой —
  секрет теряется (Windows: `ShutdownBlockReasonCreate` показывает причину, но не гарантирует).

## 9. Вход (Cloudflare Access)

- Сервис сейчас публичный (этап 1): запросы без токена. Этап 2 (Access + GitLab) — как `sdrop` без
  интерактивного терминала: `SDROP_ACCESS_TOKEN` или существующая сессия
  `cloudflared access token -app=<origin>`; при редиректе Access — сообщение «Sign in required» и
  кнопка **Sign in**, запускающая `cloudflared access login <origin>` (открывает системный браузер),
  затем повтор запроса один раз. Нет `cloudflared` — инструкция. Токен не сохраняем (его хранит
  cloudflared).
- Собственный вход через браузер с возвратом по deep link (ТЗ «Auth») невозможен без изменений на
  стороне сервиса — вне v1.

## 12. Тесты и критерии приёмки

**`core`** (без окна; фейковый сервер на `std::net`, как в тестах `sdrop`, фича `test-loopback`;
фейковые хранилище, буфер, уведомления; управляемые часы). К каждому пункту — негативный тест:

1. Ни открытого текста, ни ключа, ни ссылок, ни токена в файлах каталога данных и в stdout/stderr
   (grep контрольного секрета и его base64url/hex после прогона); индекс с лишним полем отвергается.
2. Буфер очищается через таймаут и **не** очищается, если там уже другое значение.
3. Create: отказ каждого локального действия после 201 (хранилище, индекс, буфер) → ссылки в
   памяти, Retry повторяет только неудавшееся, второго POST нет; остановка процесса между
   действиями → после запуска нет элемента хранилища без записи индекса; Enter → Esc → поздний
   201 и неизвестный исход предъявлены; create → Quit спрашивает.
4. Опрос: Waiting → Read за один интервал, ровно одно уведомление; отказ записи индекса —
   уведомления нет; без ссылки отправителя — нет запросов; после `expiresAt` — нет запросов;
   «сон» через срок и `stored` за 90 с до срока → Expired · read status unknown; `consumed`, отказ
   записи индекса, переход через срок → Read сохраняется без нового status, уведомление одно;
   404 до срока → Not found; удаление элемента хранилища после выхода из Waiting и повтор при
   запуске; отказ удаления при очистке 30 дней → запись остаётся.
5. Revoke: 204 → Revoked, 409 → Read с данными ответа.
6. Получение: до Reveal и на битой ссылке — ноль запросов; ровно один consume при двойном нажатии;
   задержанный consume + закрытие окна → результат не потерян; неверная фраза → повтор без второго
   consume; Reveal → Copy → Quit и Reveal → Copy → 30 с → Close спрашивают; Destroy только по
   подтверждению; отказ записи файла → другой путь → те же байты; сохранение в общий каталог и
   замена файла с широкими правами → итоговые права только владельца; отказ установки прав →
   данные не записаны, секрет в сессии.
7. Quick drop: `↵` создаёт и копирует ссылку; `Esc` — ничего не остаётся (буфер, индекс,
   хранилище, буферы `core`).
8. Хранилище недоступно → создание работает, запись «not tracked», в индексе ничего лишнего.

**Настоящая оболочка** (на каждой ОС, руками по чек-листу или UI-тестом GPUI test-support, где
возможно; результат — в журнал шага):

9. Quit через все входы (меню, `⌘Q`/`Ctrl+Q`, Dock, меню приложения, трей) при удерживаемом секрете
   спрашивает; Close окна D спрашивает.
10. Copy/Cut через клавиши, меню Edit и контекстное меню из каждого секретного поля (A1 текст и
    фраза, C, D текст, Open link…, фраза получателя до и после consume) проходят через
    службу буфера (concealed-пометка видна менеджеру буфера, очистка по таймеру); Undo после
    очистки формы не возвращает секрет.
11. Глобальная клавиша → C → `↵` без мыши; уведомления и клик по ним; трей; один экземпляр.
12. Ни секрета, ни ссылки в argv дочерних процессов (`cloudflared`), в логах GPUI, в заголовках
    окон и текстах уведомлений.

**Совместимость** (e2e против сервиса и `sdrop`; локально — `core/examples/dev_server.rs`): ссылка, созданная
приложением, открывается вебом и `sdrop`, и наоборот — текст, файлы, фраза; Revoke из A2 → веб
даёт 404.
